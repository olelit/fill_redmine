# Work Assistant

GUI-приложение для учёта времени: проекты, трекеры-источники (Redmine,
YouTrack, git-коммиты), ИИ-план и запись часов в выбранный трекер.
CLI больше нет — всё делается в графическом окне.

В репозитории также есть локальный MCP-сервер (`mcp_server/`) для работы из
OpenCode: он читает worklogs и коммиты, готовит план и пишет часы в YouTrack
только после явного подтверждения.

## Установка

```bash
sudo pacman -S tk
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполните `REDMINE_BASE_URL` и `YOUTRACK_BASE_URL` — это адреса инстансов,
к которым обращаются трекеры. Остальные настройки хранятся в SQLite.

## Запуск

```bash
python work_assistant.py
```

или

```bash
bash run_gui.sh
```

## Ярлык на панели KDE

```bash
bash scripts/install_desktop.sh
```

Скрипт ставит ярлык в меню приложений и пытается закрепить его на панели Plasma 6.
Если автопин не удался — закрепите вручную: ПКМ по иконке → «Закрепить на панели».

## Проекты

Главное окно — список проектов.

- **Добавить** — создать проект (имя должно быть уникальным).
- **Удалить** — удалить выбранный проект вместе с его юзерами.
- **Настройки AI** — глобальные провайдеры и ключи (см. ниже).

Двойной клик или `Enter` открывает проект.

## Проект → трекинг

Внутри проекта кнопка **Трекинг времени** открывает рабочую панель:

- блок **Настройки проекта** (можно свернуть/развернуть);
- **Трекер** — назначение, куда будут записаны часы (только трекеры с
  поддержкой записи);
- **Источник** — `Автозаполнение` (добор до рабочего дня), `Из трекера`
  (worklogs выбранного трекера-источника) или `Из коммитов` (git);
- **Трекер-источник** — появляется для источника «Из трекера»;
- **Период** — даты `с`/`по`;
- **Сгенерировать отчёт**.

Отчёт — таблица строк «юзер / дата / было / предложено / комментарий /
источник или статус». Двойной клик открывает редактор строки: часы (кратны
0.5, больше 0 и не больше 24), комментарий (пустой заменяется на
`development`), галочка «включить в трек». `Space` включает/исключает строку
без открытия редактора.

Кнопка **Затрекать** записывает включённые строки в выбранный трекер. В
источник ничего не пишется.

## Настройки проекта

- имя проекта задаётся при создании и в настройках не меняется;
- git-репозиторий (email автора задаётся у каждого юзера отдельно);
- рабочий день в часах (по умолчанию 8) и исключённые даты;
- **Юзеры**: имя, git email и отдельные ключи/идентификаторы для каждого
  трекера (`API key`, `user_id`, `activity_id`, `issue_id` для Redmine;
  `Access token`, `Issue ID` для YouTrack). Юзеров можно добавлять,
  изменять, удалять и импортировать из другого проекта.

## Глобальные настройки AI

Диалог **Настройки AI** (из списка проектов) хранит провайдера, модель, ключи
и base URL:

- **OpenCode Go** — API key и модель OpenCode Go (base URL фиксированный);
- **OpenAI** — API key и модель, `https://api.openai.com/v1`;
- **Anthropic** — API key и модель, `https://api.anthropic.com/v1`;
- **Custom** — OpenAI-совместимый endpoint: обязателен base URL.

Кнопки **Обновить модели** и **Проверить подключение** обращаются к
провайдеру. Ключи в интерфейсе маскируются, в SQLite хранятся открытым
текстом (файл БД создаётся с правами `600`).

## MCP-сервер (YouTrack fill)

`mcp_server/` — локальный stdio MCP-сервер. Он использует те же трекеры и
`GitClient`, что и GUI, но не пишет ничего без подтверждения через MCP
elicitation.

### Установка и профиль

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env                 # нужен YOUTRACK_BASE_URL
cp config/users.example.json config/users.json
chmod 600 config/users.json
```

`config/users.json` содержит токены, в git не попадает (он в `.gitignore`) и
должен иметь права `600`. Один элемент массива `users` — один профиль:

- `name`, `is_enable`;
- `git_email` — автор коммитов, по которому фильтруется `git log`;
- `youtrack.access_token` — токен YouTrack;
- `youtrack.daily_meeting_issue_id` — issue для daily meeting;
- `youtrack.daily_meeting_hours` — часы daily meeting (по умолчанию `1.0`);
- `youtrack.issue_id` — необязательный fallback, если строка плана не задаёт
  issue.

AI-ключи серверу не нужны: он не вызывает модели. Redmine-сценарии в этой
фазе не реализованы (Redmine остаётся только в GUI).

### Подключение к OpenCode

Проектный `.opencode/opencode.json` уже запускает сервер:

```json
{
  "mcp": {
    "servers": {
      "work-assistant": {
        "type": "local",
        "command": [".venv/bin/python", "-m", "mcp_server"],
        "cwd": ".",
        "codemode": false,
        "protocol": "legacy"
      }
    }
  }
}
```

Проверка подключения:

```bash
opencode mcp list   # work-assistant connected
```

### Tools и порядок работы

Сервер отдаёт ровно пять tools, без prompts и resources:

| Tool | Назначение |
| --- | --- |
| `list_enabled_users` | имена включённых профилей и их трекеры (без секретов) |
| `get_worklogs` | worklogs профиля за период |
| `get_git_commits` | коммиты профиля за период |
| `prepare_youtrack_fill` | собрать план YouTrack из коммитов и worklogs |
| `write_plan` | записать план после подтверждения |

Порядок: **read → prepare → `write_plan` approval**.
`prepare_youtrack_fill` ничего не пишет и возвращает `plan_id`, строки и
warnings; `write_plan` показывает форму подтверждения и выполняется только при
явном `approved`. План одноразовый и устаревает через 10 минут.

Период по умолчанию — с 1-го числа текущего месяца по сегодня. Issue задаётся
на уровне строки плана: `DRIVEO-XXXX` берётся из тега в subject/body коммита;
issue должен встречаться хотя бы в одном из переданных коммитов строки, иначе
план создаётся с warning (например, для дня без тегов). Часы положительные,
кратны `0.5`, а сумма с уже записанными за день не больше 8.

Daily meeting — 1 час на `youtrack.daily_meeting_issue_id` в каждый рабочий
день (Mon–Fri), если он ещё не записан. Строке daily meeting commit hashes не
нужны; для остальных строк они обязательны.

Если нужно растянуть день до 8 часов, а коммитов нет, можно передать строку
на `youtrack.issue_id` (fallback) без commit hashes: план создастся с warning.
Так добираются дни вроде 2 октября.

Форма `write_plan` — короткая сводка: количество строк, часы, период и число
предупреждений. Подробный план по датам агент печатает в чате до вызова
`write_plan`; огромный JSON в форму не попадает. Даты work item'ов пишутся по
UTC-полуночи, чтобы не сдвигаться на предыдущий день.

## Миграция со старой базы

При первом запуске `fill_redmine.db` автоматически переименовывается в
`work_assistant.db`. Старые юзеры из таблицы `users` один раз переносятся в
проекты, а проекты дополняются настройками v2. Старые таблицы не удаляются.

Путь к базе переопределяется переменной `WORK_ASSISTANT_DB`
(legacy-переменная `FILL_REDMINE_DB` тоже поддерживается).

## Новый трекер

1. Создайте `trackers/<kind>.py` с классом-наследником `BaseTracker`
   (декоратор `@register_tracker`).
2. Задайте `kind`, `label`, `fields` (`TrackerField`) и реализуйте
   `get_worklogs(start, end)`.
3. Для записи часов установите `can_write = True` и реализуйте
   `create_worklogs(records)`.
4. Импортируйте модуль в `trackers/__init__.py`, чтобы он зарегистрировался.

GUI сам покажет поля трекера в настройках проекта, колонку в таблице юзеров и
пункты в списках источника/назначения. Миграции БД не нужны.
