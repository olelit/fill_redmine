# Дизайн: удаление GUI Work Assistant

Дата: 2026-10-28  
Статус: согласован в диалоге; отдельный этап после внедрения и проверки MCP

## Цель

После того как MCP-сервер и три рабочих сценария проверены, MCP становится
единственным поддерживаемым пользовательским интерфейсом. Удалить Tkinter GUI,
его точки запуска, GUI-специфичные тесты и документацию.

## Объём

- Удалить `gui/`, `work_assistant.py` и legacy alias `fill_redmine_gui.py`.
- Удалить GUI launch/install артефакты: `run_gui.sh`, desktop entry, скрипт
  установки desktop entry и GUI-ассеты.
- Удалить тесты, которые проверяют только GUI-виджеты и GUI-валидацию.
- Обновить README и инструкции установки: описывать MCP-сервер и его локальное
  подключение вместо запуска окна.
- Удалить GUI-зависимости, если они появятся в процессе реализации и больше не
  используются.

## Сохранить

- MCP-сервер, tracker/client/service слои и тесты, нужные MCP-сценариям.
- Локальные SQLite-файлы, `.env`, `config/users.json`, legacy-конфиги и другие
  пользовательские данные; не удалять и не переписывать их автоматически.
- Трекерные API-клиенты и адаптеры, пока на них опирается MCP.

Удаление внутренних AI-клиентов или миграций SQLite не является обязательной
частью удаления GUI: неиспользуемый backend-код можно чистить отдельным
изменением после проверки ссылок и тестов.

## Проверки

- Поиск импортов и entrypoints не находит запуск Tkinter после cleanup.
- README и desktop-инструкции не предлагают запуск удалённого GUI.
- Все MCP-тесты проходят; полный `pytest` не содержит оставшихся GUI-тестов.
- Игнорируемые пользовательские файлы и локальные базы остаются нетронутыми.
