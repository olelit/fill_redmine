# Дизайн: перенос worklog'ов YouTrack → Redmine

Дата: 2026-10-30  
Статус: согласован в диалоге; ожидает review письменной спецификации

## Цель

Добавить в MCP-сервер сценарий переноса уже существующих worklog'ов из
YouTrack в Redmine. Пользователь указывает одну целевую задачу Redmine; все
часы за день суммируются и записываются в неё. Старые записи Redmine за те же
даты заменяются, чтобы повторный перенос не создавал дубли.

Спецификация уточняет и заменяет сценарий «Перенести YouTrack → Redmine» из
`2026-10-28-work-assistant-mcp-design.md`. Остальные сценарии того документа
не меняются.

## Согласованные решения

| Тема | Решение |
| --- | --- |
| Инструмент | `prepare_youtrack_transfer(user_name, issue_id, start=None, end=None)` |
| Источник | Все worklog'и профиля в YouTrack за период |
| Назначение | Один Redmine issue; ID обязателен в каждом запросе |
| Период по умолчанию | С 1-го числа текущего месяца по сегодня включительно |
| Агрегация | Сумма часов по дате; одна запись Redmine на дату |
| Комментарий | Только `redmine.comment` из JSON, без списка задач |
| Старые записи | Для каждой даты с часами в YouTrack удалить все Redmine-записи этого юзера за дату |
| Даты без источника | Не трогать Redmine |
| Запись | Только через существующий `write_plan` и MCP elicitation |
| Issue ID в JSON | Не хранить и не использовать |

## Поток данных

```text
prepare_youtrack_transfer
  ├── период: start/end или текущий месяц
  ├── YouTrack.get_worklogs(period) -> часы по датам
  ├── Redmine.get_time_entries(period) -> старые записи с ID
  ├── план: одна строка на дату + список удаляемых ID
  └── ответ: plan_id, строки, замены, warnings (без записи)

write_plan(plan_id)
  ├── неизвестный/просроченный/использованный план -> blocked
  ├── elicitation с краткой сводкой -> отказ -> blocked
  ├── проверка неизменности redmine-конфига
  ├── удаление старых записей по сохранённым ID
  └── создание новых записей, результат по каждой дате
```

## Контракт инструмента

`prepare_youtrack_transfer` принимает:

- `user_name` — имя включённого профиля;
- `issue_id` — положительный ID задачи Redmine;
- `start`, `end` — необязательные даты `YYYY-MM-DD`.

Ответ:

```json
{
  "status": "plan_created",
  "plan_id": "…",
  "user": "Oleg Litasov",
  "destination": {"tracker": "redmine", "issue": 12345},
  "period": {"start": "2026-10-01", "end": "2026-10-30"},
  "entries": [
    {
      "date": "2026-10-01",
      "issue": 12345,
      "hours": 8.0,
      "comment": "development",
      "source_issues": ["DRIVEO-2542", "DRIVEO-5177", "DRIVEO-5178"],
      "replaces": [{"id": 901, "hours": 8.0}]
    }
  ],
  "warnings": []
}
```

`source_issues` нужен только для подробного плана в чате; в Redmine он не
попадает. `replaces` показывает, какие записи будут удалены. Секреты в ответ
не включаются.

## Правила подготовки

1. Период проверяется как ISO-даты; `start > end` — ошибка. Если даты не
   переданы, используются 1-е число текущего месяца и сегодня.
2. Профиль должен быть включён и содержать рабочие `youtrack` и `redmine`
   конфиги. `redmine.comment` обязателен.
3. `issue_id` проверяется как положительное целое. Значение из
   `config/users.json` не используется.
4. YouTrack worklog'и группируются по дате. Часы суммируются; записи с
   неположительными или нечисловыми часами считаются ошибкой данных.
5. Если за период нет ни одного worklog'а YouTrack — ошибка, план не создаётся.
6. Redmine time entries читаются за тот же период по `user_id` профиля.
   Записи группируются по `spent_on`; для каждой даты источника сохраняются
   точные `id` и часы всех записей пользователя.
7. Для каждой даты источника создаётся одна строка плана с комментарием
   `redmine.comment`; `source_issues` — отсортированный список задач YouTrack.
8. Если сумма часов за дату больше 8, добавляется warning, но часы не
   обрезаются: переносится фактическое значение.
9. Даты, где есть Redmine-записи, но нет worklog'ов YouTrack, в план не
   попадают и не удаляются.
10. Если все даты источника уже имеют Redmine-записи, план всё равно
    создаётся: они будут заменены. Пустой план (нет ни одной строки) не
    создаётся.

## Удаление и запись

`WritePlan` получает неизменяемый список удалений:

```text
PlannedDeletion(date, entry_id, hours)
```

`write_plan` после подтверждения:

1. Заново загружает профиль и сверяет fingerprint `redmine`-конфига. При
   изменении конфига запись и удаление не выполняются.
2. Удаляет записи по сохранённым ID через `DELETE /time_entries/{id}.json`.
   Ответ `404` считается успехом: запись уже отсутствует.
3. Если удаление хотя бы одной записи за дату не удалось, новые записи за эту
   дату не создаются; эта дата получает статус `failed`. Остальные даты
   обрабатываются независимо.
4. Создаёт новые записи только для дат, где все удаления успешны.
5. Возвращает результат по каждой дате: `created` или `failed`. Тела ответов
   Redmine и секреты в результат не попадают.

Удаление и создание не транзисторны на стороне Redmine. При сбое после
удаления возможна потеря старой записи без новой; это осознанное следствие
режима «перезаписать», и результат должен явно показывать `failed`.

## Подтверждение

Форма `write_plan` остаётся короткой. При наличии удалений добавляется строка:

```text
Будет удалено: 20 старых записей (160 ч)
```

Количество строк, общий объём часов, пользователь, трекер и период уже
показываются существующей формой. Подробный список дат, задач-источников и
удаляемых записей выводится в чат до вызова `write_plan`.

## Ошибки и безопасность

- Нет YouTrack-worklog'ов, неверный `issue_id`, пустой/битый период,
  отсутствующий `redmine.comment`, неполный Redmine-конфиг — понятная ошибка
  без записи.
- Ошибки удаления/создания не содержат `api_key`, `access_token` и
  заголовков авторизации.
- Удаление возможно только по ID, сохранённым в immutable-плане, и только
  после положительного elicitation.
- План одноразовый, живёт 10 минут и хранится в памяти процесса.
- Никаких произвольных HTTP-запросов, shell или файловых операций инструмент
  не предоставляет.

## Тесты

- каталог MCP содержит ровно шесть инструментов, включая
  `prepare_youtrack_transfer`;
- период по умолчанию — текущий месяц;
- агрегация нескольких YouTrack-записей за день в одну строку;
- комментарий берётся только из `redmine.comment`;
- старые Redmine-записи за даты источника попадают в `replaces`, а записи за
  другие даты — нет;
- отсутствие YouTrack-worklog'ов и пустой план дают ошибку;
- warning при сумме больше 8 часов;
- `prepare` не вызывает `create_worklogs` и `delete`;
- approval показывает количество удаляемых записей и не показывает секреты;
- writer удаляет старые записи до создания новых;
- сбой удаления за дату не создаёт новую запись за эту дату, но не мешает
  остальным датам;
- `404` при удалении считается успехом;
- изменение Redmine-конфига между prepare и write блокирует запись.

## Вне рамок

- Автодозаполнение Redmine до 8 часов (`prepare_redmine_autofill`).
- Перенос Redmine → YouTrack.
- Изменения GUI.
- Хранение Redmine issue ID в JSON.
